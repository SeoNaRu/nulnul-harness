# 기존 프로젝트를 보존하며 도입하기

[English](README.md) | [한국어](README.ko.md) | [전체 사례](../README.ko.md)

**상태: 합성 프로젝트에서 수행한 실제 Claude 도입의 과거 기록. 기록일은 2026-09-08입니다.** 기존의 민감정보 제거 증거를 설명하며, 이 문서를 작성하면서 새 도입이나 다음 세션 실험을 실행하지 않았습니다.

기존 기록은 2026-09-09에 제공된 증거 검증기를 다시 통과했으며, 관련 검증기 테스트 9개도 통과했습니다. 새로운 실제 실행이 아니라 증거의 유효성을 검사한 것입니다. [로컬 검증 기록](../validation-2026-09-09.json)을 참고하세요.

## 요청과 기록된 결과

범위를 제한한 작업은 공개 NULNUL 플러그인으로 기존 프로젝트를 도입하고, 지침과 에이전트 프로필을 보존하고, 검증된 간결한 체크포인트를 만든 뒤 원래 JavaScript 라벨 정규화 작업을 계속하는 것이었습니다. 라벨의 앞뒤·중복 공백을 정리하되 대소문자를 보존하고, 대상 프로젝트 테스트에 따라 빈 입력을 처리해야 했습니다. 설정만으로 완료 처리하지 않았습니다.

| 증거 항목 | 기록된 결과 |
| --- | --- |
| 공개 플러그인 | 버전 `3.1.0`, 태그 `v3.1.0`, 출처 `github` |
| 기존 역할 | `collector`, `reviewer`를 열거하고 분류. 두 프로필 모두 전후 해시 일치 |
| 호스트 소유권 | 활성 `CLAUDE.md`, 비활성 `AGENTS.md` 해시 불변 |

| 설정·체크포인트 | 설정 검사, 체크포인트 검사, 체크포인트 완료 실행기, 문서 부채 검사 모두 종료 코드 `0` |
| 재개 준비 | `checkpoint_fast_path_ready: true` |

마지막 행은 기록 시점에 체크포인트가 준비되어 있었다는 뜻입니다. **나중의 독립된 세션이 실제 재개에 성공했다거나 Codex와 Claude가 동시에 프로젝트를 수정했다는 증거는 아닙니다.**

## 대화를 재구성하지 않고 원본 증거 확인

[민감정보를 제거한 통과 기록](../../evals/benchmarks/claude-adopt/release-3.1.0-r4.json)

```bash
python3 -m json.tool evals/benchmarks/claude-adopt/release-3.1.0-r4.json
```

제공된 검증기로 기존 기록을 검사합니다.

```bash
python3 scripts/claude_adopt_evidence.py validate \
  evals/benchmarks/claude-adopt/release-3.1.0-r4.json --version 3.1.0
```

첫 명령은 증거를 표시하고 두 번째 명령은 그 기록을 검증합니다. 어느 쪽도 실제 실행을 재현하거나 새 대상 저장소를 검증하지 않습니다. 기록에는 검사 이름과 종료 코드가 있지만 원래 임시 대상 프로젝트 전체나 완전한 재실행 명령은 없습니다. 이 저장소에서 `npm test`를 실행하는 것은 당시 대상의 완료 검사 재현이 아닙니다.

공개 소스는 커밋 `a9fd59e8c5852e8808f6698262e90d389f39f42a`로 고정되어 있습니다. 아카이브는 `nulnul-harness-3.1.0.zip`이며 SHA-256은 `7716a8ddfeb43632b4ad836c29deb1fd2981a84d423d2f2705fb88becad9e49d`입니다. [3.1.0 릴리스](https://github.com/SeoNaRu/nulnul-harness/releases/tag/v3.1.0)를 참고하세요. 이 문서를 읽는 것만으로 다운로드하거나 설치하지 않습니다.

## 기능 선택과 실패

기존 프로필을 재생성하지 않고 보존했으며, 역할 목록을 명시적으로 확인하고 분류했습니다. 활성 호스트는 자신의 진입 파일만 소유했고 비활성 호스트 진입 파일은 바이트 단위로 보존했으며, 공유 상태 작성자는 하나였습니다. 이 기록이 가능한 모든 외부 후보를 조사했다거나 최적 에이전트 선택을 입증하는 것은 아닙니다.

앞선 릴리스 실패는 [시도 1](../../evals/benchmarks/claude-adopt/release-3.1.0-failure.json), [시도 2](../../evals/benchmarks/claude-adopt/release-3.1.0-r2-failure.json), [시도 3](../../evals/benchmarks/claude-adopt/release-3.1.0-r3-failure.json)에 보존되어 있습니다. 후보를 순차적으로 수정한 것이며, 같은 고정 후보로 독립적인 성공 4회를 얻은 것이 아닙니다. 릴리스 이력에서 실패를 빼거나 노출된 회귀 사례를 새로운 홀드아웃으로 취급하지 않습니다.

## 실제 다음 세션 사례에 아직 필요한 것

1. 사용자가 승인한 폐기 가능한 대상, 고정한 작업·플러그인 버전, 보존된 원본 파일, 체크포인트에 저장한 정확한 완료 명령.
2. 민감정보를 제거한 증거와 비활성 호스트 진입 파일 보존을 남긴 첫 세션 완료.
3. 실제로 새로 시작한 세션이 검증된 체크포인트와 직접 필요한 작업 파일만 읽고, 체크포인트에 저장된 완료 명령을 실행한 뒤 범위가 정해진 후속 변경을 완료하는 과정.
4. 오래되거나 잘못된 체크포인트 증거를 그대로 신뢰하지 않고 빠른 재개를 차단하는 음성 대조군.

이는 다음 실험의 명세이지 실행한 결과가 아닙니다. 두 번째 상태 작성자를 만들거나 비공개 대화를 공개 입력으로 복사하지 말고 기존 체크포인트·호스트 소유권 기능을 사용해야 합니다. 실제 모델 실행, 자격 증명 사용, 외부 설치에는 명시적 승인과 고정 예산이 필요합니다.

## 측정 한계

인용한 민감정보 제거 기록은 결과를 담지만 시간·비용 전체를 담지는 않습니다. 이 사례집의 실행 시간, 토큰 수, 금전 비용은 `unknown`입니다. 합성 유틸리티를 이용한 릴리스 도입 스모크 테스트이며, 고객 운영 실적, 독립 재현, 품질 A/B 승리, 폭넓은 프로젝트 간 전이 증거가 아닙니다.
