# 스튜디오 시간 예약하기

[English](README.md) | [한국어](README.ko.md) | [전체 사례](../README.ko.md)

**상태: 2026-09-09 로컬 HTTP 검사와 Chromium 검사 9개 통과.** 여전히 앞으로 NULNUL 실험에 사용할 참조 구현이지, 측정된 하네스 실행이 이 앱을 생성했다는 증거는 아닙니다. 고정된 3.1.0 릴리스 이후 추가했습니다. 경과 시간, 토큰, 금전 비용, 비교 우위는 `unknown`입니다. [소스 해시가 포함된 검증 기록](../validation-2026-09-09.json)을 참고하세요.

## 요청과 결과물

> 로컬 스튜디오 예약 화면과 API를 만들어 주세요. 가능한 시간을 보여주고 가상의 이름을 받아 예약하되, 같은 시간의 중복 예약은 막아 주세요. 계정, 결제, 추가 설치, 외부 서비스는 사용하지 마세요.

[app.py](app.py) 하나에 브라우저 화면, JSON API, 메모리 SQLite 저장소, 범위를 제한한 HTTP 검사가 들어 있습니다. 실행에는 Python 3.9 이상만 필요하며, 글꼴이나 브라우저 자산을 내려받지 않습니다. 화면은 영어입니다.

## 실행

저장소 루트에서 실행합니다.

```bash
python3 examples/booking-service/app.py
```

`http://127.0.0.1:8765`를 여세요. 가상의 이름과 시간을 선택해 예약한 뒤 새로고침하면 변경된 예약 가능 상태를 볼 수 있습니다. 기본 포트를 사용 중이면 `--port 8766`을 붙이세요. Ctrl+C로 종료하면 모든 예약이 사라집니다.

## 완료 검사 명령

```bash
python3 examples/booking-service/app.py --check
```

검사는 사용 가능한 포트에 임시 루프백 서버를 엽니다. HTML 응답, 초기 시간 4개, 예약 성공, 중복 예약의 `409` 거절, 잘못된 JSON, 필드명·타입 오류, 잘못된 시간·이름, 지원하지 않는 Content-Type, 신뢰하지 않는 Origin·Host, 거절 후 예약 상태 보존을 assertion으로 확인합니다. 브라우저는 실행하지 않습니다. assertion을 비활성화하는 Python `-O` 옵션으로 실행하지 마세요.

같은 HTTP 검사를 저장소의 일반 CI unittest 모음에 포함했습니다. Claude나 다른 모델을 호출하지 않고 해당 회귀 테스트만 실행할 수 있습니다.

```bash
python3 -m unittest discover -s tests -p 'test_booking_service_example.py' -v
```

브라우저 검사는 Chromium 147.0.7727.101에서 별도로 수행했습니다. 예약과 새로고침, 오래된 탭의 중복 예약 거절, 가로 넘침이 없는 390픽셀 화면, 키보드 선택·제출, 동작 줄이기 설정, 마크업 형태 이름의 텍스트 표시, 전체 예약 완료 상태를 확인했습니다. JavaScript 런타임 오류는 관찰하지 않았습니다. 범위를 제한한 브라우저 검사이며 포괄적인 접근성·브라우저 호환성 감사는 아닙니다. 브라우저의 `/favicon.ico` 요청은 `404`를 반환했으며, 동작을 막지 않는 이 누락은 수정하지 않았습니다.

## API 계약

| 요청 | 기대 응답 |
| --- | --- |
| `GET /api/slots` | `200`, `time`과 `available`이 있는 `slots` |
| `POST /api/bookings`에 `{"slot":"09:00","name":"Example Guest"}` 전송 | `201`, `slot`과 `name`이 있는 `booking` |
| 같은 시간으로 재요청 | `409`. 원래 예약 보존 |
| 필수 필드 `name` 대신 `guest` 사용 | `400`. 예약 생성 안 함 |

POST에는 `application/json`, `Content-Length`가 있는 크기 제한 본문이 필요하며, Origin 헤더가 있으면 같은 출처여야 합니다. 화면은 별도의 가짜 예약 목록이 아니라 실제 API 응답 필드를 사용합니다.

## 기능 선택

이 참조 구현은 Python 표준 라이브러리와 브라우저 기본 기능으로 직접 작성했습니다. 새로운 에이전트, 스킬, 플러그인, MCP 서버, 외부 연동을 설치하지 않았습니다. 이후 하네스 실험에서는 먼저 시작 프로젝트와 설치된 역할 목록을 확인하고, 경쟁력 있는 기존 기능을 재사용하며, 구체적인 결과·검증 공백이 있을 때만 역할을 추가해야 합니다. 그 실험의 실제 선택 과정은 아직 관찰하지 않았습니다.

잘못된 필드와 중복 예약은 생산자·소비자 경계와 음성 대조군을 구체화합니다. 앱 검사를 통과하더라도 검사한 앱 동작의 근거일 뿐, NULNUL 품질 우위의 근거는 아닙니다.

## 한계와 다음 증거

가상의 하루만 다루며 프로세스 내부 저장소와 순차 요청 처리기를 사용합니다. 인증, 캘린더 연동, 취소, 결제, 운영 배포는 없습니다. 의도적으로 루프백에만 바인딩합니다. 실제 개인정보를 입력하거나 프록시를 통해 외부에 노출하지 마세요.

비교 측정에서는 이 완성 답안이 아니라 동일한 작업 명세와 합의된 시작 파일에서 각 조건을 출발시킵니다. [사례집 비교 규칙](../README.ko.md#우위-주장보다-먼저-비교)에 따라 실패와 설정 비용을 기록하고, 독립적인 검사 결과를 첨부한 뒤 증거 상태를 변경해야 합니다.
