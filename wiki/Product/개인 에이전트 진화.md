# 개인 에이전트 진화

## 결정

하네스는 오류 보고를 사용자에게 되돌리는 데서 멈추지 않는다. Worker가 관찰·기대·재현 근거를 보내면 Coach가 원인을 분류해 한 가지 에이전트 버전 변경을 제안하고, 독립 Gate가 기존 버전과 비교해 승격·거부·롤백한다. Navigator는 검증된 체크포인트를 저장하고 원래 프로젝트를 이어간다.

```text
Worker feedback → Coach proposal → independent Gate
       ↑                                   │
       └────── Navigator resumes work ─────┘
```

역할은 책임 경계이지 항상 네 개의 실행 에이전트를 뜻하지 않는다. 평소에는 합칠 수 있지만 제안자는 자기 업그레이드의 Gate가 될 수 없다. Coach 자체의 결함도 Coach 대상 피드백과 새 버전으로 처리하며, 재귀적인 “Coach의 Coach”는 만들지 않는다.

## 남기는 상태

다중 세션일 때만 `docs/nulnul/evolution.json`을 만든다. 채팅 전문이나 로그를 보관하지 않고 다음만 남긴다.

- 검증된 목표·마일스톤·완료 검사·다음 행동
- 에이전트별 현재 버전과 마지막 승격
- 관찰·기대·최소 재현 근거가 있는 피드백
- 단일 변경 제안, 비교 결과, 롤백
- 사용자가 승인한 권한 변화

표준 라이브러리 검사기는 대상 또는 선언된 제안 작성자의 자기 승인, 깨진 승격 이력, 잘못된 버전 이동, 깨진 참조, 실패한 회귀 검사의 승격, 미승인 권한 확대와 민감 키 저장을 거부한다. 이는 상태 기록의 구조적 검증이며 실행자 신원을 암호학적으로 증명하지는 않는다.

## 범위

기본 학습 범위는 해당 에이전트나 프로젝트다. 여러 대표 프로젝트에서 일반화됐거나 사용자가 명시적으로 개인화를 요청한 경우에만 개인 범위로 올린다. 개인 경로와 데이터는 공개 플러그인에 넣지 않는다. 공개 코어 변경은 교차 프로젝트 근거와 별도 공개 승인이 필요하다.

## 현재 근거

- 독립 Gate의 Coach v2 승격: 통과
- Coach 자기 승인: 거부
- 미승인 `publish` 권한 확대: 거부
- 유효하지 않은 체크포인트 재개: 거부
- 비정상 형식 입력: 예외 대신 검증 오류 반환
- 연속된 다중 승격 이력과 거절된 대안 보존: 통과
- 선언된 제안 작성자와 Gate가 같은 승격: 거부
- 전체 자동 검사 27건 및 Harness 100: 통과

실제 장기 품질 향상률은 아직 주장하지 않는다. 반복 프로젝트에서 승격 후 지표가 좋아지는지 별도 A/B 근거가 필요하다.
