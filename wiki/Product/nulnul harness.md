# nulnul harness

## 한 문장

검증된 능력을 찾아 프로젝트별 실행 시스템으로 조립하고, 실제 결과가 좋아진 변경만 남기는 Codex 하네스.

## 제품 루프

```text
Discover → Verify → Assemble → Run → Measure → Evolve
```

| 단계 | 남겨야 할 증거 |
| --- | --- |
| Discover | 필요한 작업과 확인한 기존 후보 |
| Verify | 출처·호환성·품질·권한·라이선스와 선택 이유 |
| Assemble | 활성 능력과 각 에이전트의 구체적인 역할 |
| Run | 실제 결과물과 완료 검사 |
| Measure | 성공률·정확도·중복률·비용·시간·사용자 개입 |
| Evolve | 동일 평가의 전후 결과와 롤백 조건 |

## 경쟁 기준

전문성은 문서 수나 에이전트 수가 아니라 다음으로 판단한다.

1. 실제 결과를 실행했는가.
2. 동일 조건에서 반복 가능한가.
3. 품질뿐 아니라 토큰·시간·설정 비용을 포함했는가.
4. 실패와 원본 평가 자료를 숨기지 않았는가.
5. 개선이 나빠지면 자동으로 버릴 수 있는가.

## 만들지 않는 것

- 근거 없는 아키텍처 패턴 목록
- 역할이 겹치는 에이전트
- 검증되지 않은 성능 문구
- 실험 없이 추가하는 MCP·서비스·전역 설정

## 릴리스 문턱

- 대표 워크플로 하나가 끝까지 실행된다.
- 실제 코드 또는 데이터가 자동 검사된다.
- 하네스 없음/있음 비교를 같은 모델과 조건으로 최소 3회 반복한다.
- 테스트 성공률, 사람 개입, 토큰, 시간과 실패가 함께 공개된다.
- 외부 사용자가 명령 하나로 결과를 재현한다.

현재 행동·안전 릴리스 게이트는 [[Harness 100]]에서 100/100을 통과했다. 실제 품질 향상률은 별도 A/B 증거가 생기기 전까지 주장하지 않는다.
