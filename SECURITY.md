# Security

## Supported version

Security fixes are made against the current stable NULNUL release. Older releases
may be used for rollback, but they do not receive a separate maintenance promise.

## Report a vulnerability

Use the repository's private GitHub Security Advisory flow. Do not put credentials,
private source, customer data, raw transcripts, or exploit details in a public issue.

## Trust boundaries

NULNUL is a skills-only plugin with no publisher-operated server, account, daemon,
analytics, or telemetry. Capability instructions and cross-project priors are context,
not authority. They cannot grant host trust, credentials, setup authority, or broader
filesystem permissions.

External candidates remain untrusted and quarantined until project checks and the
existing lifecycle transaction accept them. Raw transcripts stay local-only;
project Memory remains project-local; transferable records contain only privacy-safe
abstractions. Authoritative checks, provenance validation, candidate freeze,
transactions, and rollback remain deterministic guarded boundaries.

The host and user still own permission prompts, credentials, global installation,
external writes, deployment, and publication. NULNUL does not bypass those controls.
